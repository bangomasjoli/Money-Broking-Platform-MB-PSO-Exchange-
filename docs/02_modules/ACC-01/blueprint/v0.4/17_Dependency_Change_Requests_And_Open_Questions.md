# ACC-01 Account Structure
## 17 Dependency Change Requests, Open Questions and Human Decisions (v0.4)

ACC-01's ownership is `docs/02_modules/ACC-01/**` and `docs/03_implementation/tasks/ACC-01/**` only. Everything below that needs another module, a shared foundation, a master document or a governance register **stops here as a request**. **None of it has been made, agreed or scheduled by the owning module; no owning module has changed.** A human promotes findings to `OPEN_FINDINGS.md` and decisions to `DECISION_LOG.md`.

## 1. Classification (RF-10)

Every DCR carries exactly one class:

| Class | Meaning |
|---|---|
| **ACC-BUILD** | Blocks building the named ACC-01 phase (peers may be labelled test doubles) |
| **ACC-REAL-USE** | Does **not** block building against labelled test doubles; blocks the **real** (non-test-double) satisfaction of the named `DEP-*` prerequisite of file 01 §4.5 — in every environment. **(R2)** This is a dependency state, **not** an environment state (ACC-R2-HD-06). **(R3, ACC-R3-HD-03)** For a *runtime* dependency the DCR delivers the **behavioural evidence seam** ACC-01 verifies per operation (a configured version never suffices); for a *governance-only* dependency it delivers the **authoritative governance record** that a later, separately approved ACC-01 code change may cite to remove the hard gate |
| **LED-DESIGN** | Blocks **LED-01's** design/schema freeze — not ACC-01's build |
| **GO-LIVE** | Blocks go-live/use of a dependent capability or the environment-availability decision, not ACC-01 build or dependency satisfaction |
| **GOV** | Governance hygiene (registers, masters); blocks nothing technical |
