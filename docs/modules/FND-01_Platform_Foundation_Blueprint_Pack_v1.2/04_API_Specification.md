# FND-01 Platform Foundation  
## 04 API Specification

## 1. API Scope

FND-01 exposes foundation APIs only.

It does not expose business, trading, money movement, compliance, or admin override APIs.

---

## 2. API Standards

### 2.1 Common Headers

| Header | Required | Description |
|---|---:|---|
| `X-Request-ID` | Optional from caller / generated by server | Unique request identifier |
| `X-Correlation-ID` | Optional from caller / generated by server | Cross-service trace ID |
| `Idempotency-Key` | Required for idempotent actions where applicable | Durable duplicate prevention |
| `Authorization` | Required for protected endpoints | Auth token |
| `X-Client-Scope` | Not trusted from client | Server-derived only |

### 2.2 Standard Success Response

```json
{
  "success": true,
  "request_id": "req_...",
  "correlation_id": "corr_...",
  "data": {},
  "server_time_utc": "2026-01-01T00:00:00Z"
}
```

### 2.3 Standard Error Response

```json
{
  "success": false,
  "request_id": "req_...",
  "correlation_id": "corr_...",
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "The request is invalid.",
    "details": []
  },
  "server_time_utc": "2026-01-01T00:00:00Z"
}
```

Rules:

1. Error message must not leak secrets.
2. Internal stack traces must not be returned.
3. Correlation ID must be included.
4. Server UTC must be included.
5. Sensitive vendor payloads must not be returned.

## 3. Endpoints

### 3.1 GET `/foundation/health`

Purpose: liveness check.

Auth: none or internal-only depending deployment.

Response:

```json
{
  "success": true,
  "data": {
    "status": "alive"
  }
}
```

### 3.2 GET `/foundation/readiness`

Purpose: readiness check for deployment/load balancer.

Auth: internal-only.

Response:

```json
{
  "success": true,
  "data": {
    "status": "ready",
    "checks": [
      {"name": "database", "status": "pass"},
      {"name": "queue", "status": "pass"},
      {"name": "time_sync", "status": "pass"},
      {"name": "licence_lock_interface", "status": "pass"},
      {"name": "audit_outbox", "status": "pass"}
    ]
  }
}
```

### 3.3 GET `/foundation/version`

Purpose: expose build/release metadata.

Auth: internal/staff-admin only in production.

Response:

```json
{
  "success": true,
  "data": {
    "application": "aix-money-broking-platform",
    "release_version": "v0.0.0",
    "artifact_hash": "sha256:...",
    "build_time_utc": "2026-01-01T00:00:00Z",
    "environment": "production"
  }
}
```

### 3.4 GET `/foundation/modules`

Purpose: list registered modules and activation status.

Auth: Admin / Auditor / Tech Admin.

Response:

```json
{
  "success": true,
  "data": [
    {
      "module_code": "FND-01",
      "module_name": "Platform Foundation",
      "version": "v1.0",
      "status": "active",
      "owner": "Technology",
      "runtime_enabled": true
    }
  ]
}
```

### 3.5 GET `/foundation/time`

Purpose: verify server-authoritative UTC.

Auth: internal/staff-admin where production.

Response:

```json
{
  "success": true,
  "data": {
    "server_time_utc": "2026-01-01T00:00:00Z",
    "time_source": "ntp_synced",
    "clock_drift_status": "normal"
  }
}
```

### 3.6 POST `/foundation/smoke-test`

Purpose: run non-destructive foundation smoke checks.

Auth: Tech Admin / Deployment Service Identity.

Request:

```json
{
  "scope": "post_deploy",
  "release_id": "rel_..."
}
```

Response:

```json
{
  "success": true,
  "data": {
    "smoke_test_id": "smoke_...",
    "status": "passed",
    "checks": []
  }
}
```

Rules:

1. Must not create uncontrolled financial state.
2. Must not bypass feature flags.
3. Must produce audit/deployment evidence.


### 3.7 GET `/foundation/scheduler/jobs`

Purpose: read registered scheduled jobs.

Auth: Tech Admin / Security Admin / Auditor.

Response:

```json
{
  "success": true,
  "data": [
    {
      "job_code": "daily_safeguarding",
      "owner_module": "MON-XX",
      "criticality": "critical",
      "schedule": "RRULE:FREQ=DAILY",
      "enabled": true,
      "missed_run_detection": true
    }
  ]
}
```

### 3.8 POST `/foundation/scheduler/jobs/register`

Purpose: register a scheduled job from an approved module.

Auth: Internal service / deployment service identity.

Request:

```json
{
  "job_code": "daily_safeguarding",
  "owner_module": "MON-XX",
  "schedule": "RRULE:FREQ=DAILY",
  "criticality": "critical",
  "max_lateness_minutes": 30,
  "idempotency_strategy": "job_code_period"
}
```

Rules:

1. Invalid module owner is rejected.
2. Critical jobs require missed-run detection.
3. Registration is audit logged.

### 3.9 GET `/foundation/scheduler/runs`

Purpose: read job run status and missed-run status.

Auth: Tech Admin / Security Admin / Auditor.

### 3.10 POST `/foundation/jobs/enqueue`

Purpose: internal interface to enqueue background work.

Auth: Internal service identity only.

Request:

```json
{
  "job_type": "example.job",
  "owner_module": "FND-01",
  "payload_ref": "payload_...",
  "correlation_id": "corr_...",
  "causation_id": "evt_...",
  "source_ref": "entity_...",
  "idempotency_key": "job_key_..."
}
```

Rules:

1. Public clients must not call this endpoint.
2. Payload should be reference-based where sensitive.
3. Job must carry correlation ID.

### 3.11 POST `/foundation/rate-limit/check`

Purpose: internal rate-limit decision interface.

Auth: API gateway / internal service identity.

Request:

```json
{
  "scope_type": "actor_ip_client_action",
  "actor_id": "user_...",
  "client_id": "client_...",
  "action": "login",
  "source_ip": "203.0.113.10"
}
```

Response:

```json
{
  "success": true,
  "data": {
    "decision": "allow",
    "limit_ref": "rl_...",
    "retry_after_seconds": null
  }
}
```

## 5. Error Codes

| Code | HTTP | Meaning |
|---|---:|---|
| `FOUNDATION_NOT_READY` | 503 | Foundation readiness check failed |
| `REQUEST_CONTEXT_INVALID` | 400 | Request context missing/invalid |
| `CORRELATION_ID_INVALID` | 400 | Correlation ID invalid |
| `MODULE_NOT_REGISTERED` | 403/500 | Module is unknown |
| `MODULE_DEPENDENCY_NOT_MET` | 409 | Module dependency missing |
| `FEATURE_FLAG_UNAVAILABLE` | 503 | Feature flag interface unavailable |
| `LICENCE_LOCK_UNAVAILABLE` | 503 | Licence lock interface unavailable |
| `TIME_SOURCE_UNHEALTHY` | 503 | Trusted time source unhealthy |
| `CONFIGURATION_INVALID` | 500 | Critical config invalid |
| `CONFIGURATION_DRIFT` | 409 | Runtime config drift detected |
| `SMOKE_TEST_FAILED` | 500 | Deployment smoke test failed |
| `MODULE_BOUNDARY_VIOLATION` | 500 | Cross-module boundary violation |
| `SCHEDULED_JOB_MISSED` | 500/alert | Scheduled job missed run window |
| `JOB_QUEUE_DEAD_LETTER` | 500/alert | Job moved to dead-letter |
| `RATE_LIMITED` | 429 | Request throttled |
| `DB_ISOLATION_VIOLATION` | 500/alert | Runtime DB grant/RLS violation |
| `ASYNC_CORRELATION_MISSING` | 500/alert | Async job missing correlation context |
