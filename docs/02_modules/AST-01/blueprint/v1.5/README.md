## What changed from v1.4

| Finding | Sev | v1.5 |
|---|---|---|
| **F32(a) — still open in v1.4, part (a) only** The "a referenced canonicaliser version is frozen" rule was exact but had no concrete enforcement mechanism | LOW | New insert-only `ast1.address_rule_version` (the frozen semantic implementation of each referenced pair) and `ast1.address_rule_vector` (frozen golden vectors), both trigger-immutable for every role. New `ast1.assert_address_rules_frozen()`, called by every migration that touches the canonicaliser, the address-rule tables, `network_registry` or `instrument` identity columns: it verifies, for every referenced pair, that the registry row exists, its semantic digest is unchanged, the full vector set exists and reproduces exactly, every stored instrument value is still a fixed point under its own version, and no collision exists — aborting the migration on any failure. `network_registry` may now name only a registered, vectored pair. `08`'s event wording corrected from "the current network rule" to "the instrument's own stored version" |
| **AST-01-F33 (new)** — The class-binding concurrency proof rested on an application-only lock step; SQL did not force the correction to lock instruments before changing the class | LOW | `trg_asset_class_frozen` branch (b) itself calls `ast1.lock_asset_instruments(asset_id)` — locking every instrument of the asset, record-less ones included — **before** permitting the class change, for any writer regardless of whether it followed the documented apply protocol. The record-insert trigger is restated as one fixed-order function so the `SECURITY_LABELLED` check reads `NEW.asset_class_at_record` (set earlier in the same function), removing the unspecified-firing-order ambiguity. The first-classification race is adjudicated: with the lock in place, exactly two interleavings are possible and neither produces a `NON_SECURITY` record stamped with a `SECURITY`/`SECURITY_TOKEN` class. A round-trip `A → B → A` correction with no intervening classification is stated explicitly: it does not revive a stale record on its own; the deferred constraint refuses the second hop wherever a record still predates both |
| **AST-01-F34 (new, supersedes F31's residue)** — The intra-level guard and the "idempotent re-lock" exception were not mechanically defined; literal implementation would false-trip `AS006` on the normal merge, real-`SECURITY`, correction and consume paths | LOW | The lock tracker is now a fully specified, transaction-local (`set_config(…, true)`) data structure holding the **set** of held keys per level with mode, not only the last id. A same-or-stronger-mode request on a held key is a documented no-op; a stronger-mode request on a held key fails closed (`AS006` — no in-transaction upgrade); a multi-row set request drops already-held members and checks only the new ones against the highest previously acquired id. State reverts automatically, together with the row locks it describes, at `COMMIT`, `ROLLBACK` and `ROLLBACK TO SAVEPOINT`, with no dependence on `BEGIN` or pooler behaviour — removing the v1.4 text's incorrect reliance on both |
| **AST-01-F35 (new)** — Recency/ordering residue: (a) a delayed `ADMITTED` attestation could win after a `WITHDRAWN` row; (b) "the newest `SECURITY` record's bundle" named no ordering key; (c) the pack disagreed with itself on the marker sequence source | LOW | **(a)** `trg_attestation_binding` refuses an `ADMITTED` insert outright for a `(instrument, admission_ref)` pair that already has a `WITHDRAWN` row, independently of `attestation_seq`; re-admission needs a new `admission_ref` from `EXM-01`'s own lifecycle (DCR-AST1-004 updated). **(b)** The elevated-evidence exclusion rule now names `global_seq` and excludes the bundle of **every** qualifying `SECURITY` record over every basis tree, not "the newest" one — strictly tighter, no recency choice needed. **(c)** `class_correction_marker.marker_global_seq` is stated once, consistently, as drawn from the shared `ast1.classification_global_seq` (INV-21, 05 §5.3, §7.1 S8 aligned) |
