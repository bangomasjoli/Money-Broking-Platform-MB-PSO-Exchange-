## Deliberate choices and departures — for the re-reviewer

1. **F29's fix is chosen over the review's minimum.** The review offered two options: a full `record_fingerprint_matches`-style second column, or "at minimum" the deferred-constraint assertion. v1.4 does **both**: the deferred constraint (writer correctness) **and** the independent `asset_class_at_record`/`class_binding_matches` check (the actual security control), because only the latter is correct regardless of whether the fingerprint recompute has a defect — the deferred constraint alone would still leave B12 silent if a writer's fingerprint recompute silently no-ops in a way the constraint's equality check happens not to catch (for example, by computing a value that happens to differ from the *old* one but does not reflect the *new* class either). The class-binding check has no such failure mode because it does not depend on any recompute at all.
2. **`AS007` is a new SQLSTATE, not an overload of `AS006`.** The review offered either. A new code was chosen because the two failure classes are operationally distinct: `AS006` (lock-set grew, or now, an intra-level ordering violation) is a **contention/caller-order** condition that is sometimes retriable; `AS007` (wrong isolation level) is a **pool-configuration** condition that is never retriable without fixing the connection pool. Conflating them would make an operator's triage harder, not easier.
3. **Where the isolation assertion lives.** Rather than adding it to every individual trigger, it is placed once at the start of `authoritative_state()` and once at the start of each lock helper. Every security-relevant SQL path in the pack goes through one or the other (mint/consume/backstop calls go through `authoritative_state()`; every writer goes through a lock helper), so this is exhaustive without being repeated per-trigger.
4. **`lineage_root()`'s cycle bound (4096 hops) is illustrative, not load-bearing.** Merges are rare, governed, human-approved events; a real lineage chain will never approach this. The number exists only so the function has *some* fail-closed bound rather than an unbounded loop, and is a parameter the implementation task may tune.
5. **F31's re-derivation reads `asset`/`instrument_underlying` without an instrument lock.** This is deliberately safe, not an oversight: the exclusive lineage gate, already held at that point, excludes every writer that could change which instruments belong to the tree or wrap it (classification writers wait on the gate `SHARE`; instrument inserts wait on the asset row `SHARE`; underlying links only attach in `DRAFT`, which has no record and so nothing to narrow). The set is still re-derived after every lock is taken and `AS006` is raised if it grew, as v1.3 already did.
6. **F32(a) leaves `network_registry.canonicalisation_version` itself an ordinary mutable column.** The immutability is on the **function's case for a referenced version**, not on the registry row. This is the minimum change that satisfies the instruction ("once any instrument references a pair, that pair's semantics are immutable forever") without freezing the registry's ability to adopt a new version for future registrations, which the pack has always allowed.
7. **`attestation_seq` is its own sequence**, not drawn from `ast1.classification_global_seq`. The securities-market attestation domain is unrelated to the classification/lineage ordering domain (design rule 12/18 explicitly scope that shared sequence to records, merges and evidence); mixing them would only make the shared sequence's proven scope harder to state precisely, which is exactly what F30(c) asked to avoid.
