## 6. Design choices the reviewer may want to test

These are v0.6 authoring decisions inside the approved decisions, not new decisions:

1. **Explicit `abort_target_*` columns plus a new deferred trigger (`trg_acc1_recovery_scope`)**, rather than keying the `CHECK` on `family_role = 'master'` alone. A row-level `CHECK` cannot see the other rows of an abort, so the cross-row facts the review wanted non-implicit (one target, target status agreed by every row, exact family set, no partial recovery) are enforced at commit.
2. **A cited member's rejection must be current.** In a master abort, `checker_rejected_seal` may cite a master-directed member's rejected seal only if that member has no applied seal at its current cycle; a rejection superseded by a later successful seal of the same member is refused (T-282). This mirrors the "latest row" rule of 1a.
3. **An `independent_preserved` member's "formal withdrawal" (R5-F02)** is recorded by the master abort's own maker-checker request citing the member's `independent_initiation_id` — no separate withdrawal record is invented, because the member's own abort is illegal while its master is `closing`. The member's own governed withdrawal follows afterwards as an ordinary independent abort (T-288).
4. **`DEP-IAM-SEAL-REJECTION-EVIDENCE` is modelled as a runtime dependency that is hard-unsatisfied in the production composition root** (like the governance-only gates) and refused with `evidence_failure = SEAM_ABSENT`, not `GOVERNANCE_HARD_UNSATISFIED`, because its eventual evidence is runtime, not a governance record. Lifting it needs DCR-ACC-IAM-08 delivered and accepted **and** an approved ACC-01 code change.
5. **FND-02 is named against every runtime `DEP-*` rather than a new `DEP-*` id**, and one new `evidence_failure` code, `PEER_NOT_AUTHENTICATED`, is added (08, 09, 01, 11, 14, 17). The existing codes could not express "no authenticated peer identity".
6. **Attester contract version is strict.** Same authenticated identity + same `contract_id` + same contract version binds; any post-seal contract change never binds and is `attester_contract_fault` evidence. No re-verification rule for a contract change after the seal is invented.
7. **`unavailable` rows with no authenticated answer** carry a NULL identity but are still bound by the database to the pinned slot, pin and seal version, so an unreachable or de-configured pinned attester still grounds `family_completion_unattainable` (T-300), while a `clear` row can bind only from the pinned identity.
8. **`ACC1_CLOSURE_APPROVAL_STALE` is reused for a stale abort** (extended in 09) rather than adding a new code, because it already means "the approved payload no longer matches the live target".
9. **One new requirement, ACC-REQ-058** (R5-F04: authenticated attester identity and non-empty pinned set); ACC-REQ-045, -055, -056 and -057 are amended. No other requirement is new.
10. **`family_completion_unattainable` vocabulary explained, not consolidated** — same predicate as `postseal_attestation_*`; it is the master-only, family-scoped label (`CHECK` restricts it to master aborts). Consolidating would have changed which codes a master abort may cite for member evidence (T-237), a change no finding asked for.
11. **No test was renumbered.** Flagged rows were rewritten in place with [v0.6] markers; all new tests are appended as T-276…T-306.
12. **Same-class precision fixes beyond the two named rows.** R5-F06.1 named 07 §2 `close_initiate` and `close_collect_evidence`; the identical unqualified "real entitlement" phrase in 07 §2 `close_complete` and 04 §2.4 was qualified too, so that T-275/T-306's sweep claim is true.
